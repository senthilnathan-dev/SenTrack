# AI assistant (phase 8, first slice)

Principles: **optional, off by default, user's own key, nothing automatic.**

* `core-ai`: `AiProvider` (Gemini, OpenAI, Claude), `AiProtocol` (builds each provider's HTTPS request and reads the
  reply; pure and unit-tested), `AiClient` (one POST with `HttpURLConnection`, friendly errors). The API key goes in a
  request **header**, never in the web address.
* `AiSettingsStore` (app) keeps enabled flag, provider, model and key in the encrypted database's `meta` table, so the key
  is encrypted at rest and travels inside encrypted backups.
* Settings -> More -> **AI assistant**: switch, provider, model, key; then the **Assistant**: paste text, choose
  Summarize / Make clearer / Fix spelling and grammar / Custom, see **the exact text that will be sent**, tap Send, copy
  the result.
* The privacy policy text names this feature; keep it in step.

Not built yet: on-device model (the intended default; needs a model runtime and a download flow), using AI from inside
notes, answering questions about your data (needs careful, explicit selection of what to share), usage limits.
Copying a result puts it on the system clipboard, which other apps can read; the screen says nothing about this yet.

## On-device model (added)

* **Runtime**: Google's LiteRT-LM (`com.google.ai.edge.litertlm:litertlm-android:0.18.0`), running `.litertlm` files on the
  CPU/GPU of the phone. Nothing is sent anywhere.
* **Models**: not bundled (too large for a Play install) and not downloaded by SenTrack. Gemma's files are gated behind a
  licence the user must accept on Hugging Face, so the user downloads the file and **imports** it
  (`LocalModelStore`, private `files/models`, one model at a time, excluded from backups by living outside the vault).
  Catalog (`LocalModels`): Gemma 3 1B int4 (about 584 MB, recommended first) and Qwen 2.5 1.5B q8 (about 1.6 GB, Apache 2.0).
* **Compatibility test** ("Test my phone"), all in `core-ai/local`:
  1. `DeviceCheck`: 64-bit ARM, RAM (total and free vs. what the model needs), free storage, low-memory class, heat.
     Hard failures block the test; warnings do not.
  2. `LocalLlm.benchmark()`: load time, a speed run that streams a paragraph (time to first word, tokens/second),
     then two accuracy prompts (fix a bad sentence; summarize while keeping a rupee amount exact).
  3. `BenchmarkScoring.verdict`: Good (>= 8 tokens/s and first word <= 4 s), Usable (>= 3), Too slow (< 3), or Poor answers
     (failed both accuracy checks). The thresholds live in one object and are a first estimate to be tuned on real phones.
  4. The verdict is saved with the model name; the on-device switch only unlocks for Good or Usable, and a Too slow or
     Poor result turns it off.
* **Unit-tested**: `DeviceCheck`, scoring, quality checks, stream joining (`LocalAiTest`). The benchmark itself and
  model loading can only be exercised on a phone.
* **Known unknowns**: LiteRT-LM's message objects are read with `toString()`; if the text comes back wrapped, adjust
  `LocalLlm`. Whether the A34's GPU is used, and real tokens/second on it, will be learned from the first test run.
