# AI assistant (phase 8, first slice)

Principles: **optional, off by default, user's own key, nothing automatic.**

* `core-ai`: `AiProvider` (Gemini, OpenAI, Claude), `AiProtocol` (builds each provider's HTTPS request and reads the
  reply; pure and unit-tested), `AiClient` (one POST with `HttpURLConnection`, friendly errors). The API key goes in a
  request **header**, never in the web address.
* `AiSettingsStore` (app) keeps enabled flag, provider, model and key in the encrypted database's `meta` table, so the key
  is encrypted at rest and travels inside encrypted backups.
* Settings -> More -> **AI assistant**: switch, provider, model, key; then the **Assistant**: paste text, choose
  Summarize / Make clearer / Fix spelling and grammar / Custom, see **the exact text that will be sent**, tap Send, copy
  the result.
* The privacy policy text names this feature; keep it in step.

Not built yet: on-device model (the intended default; needs a model runtime and a download flow), using AI from inside
notes, answering questions about your data (needs careful, explicit selection of what to share), usage limits.
Copying a result puts it on the system clipboard, which other apps can read; the screen says nothing about this yet.

## On-device model

Goal: **no manual steps.** One tap sets everything up inside the app.

* **Runtime**: Google's LiteRT-LM (`com.google.ai.edge.litertlm:litertlm-android:0.18.0`), running `.litertlm` files on the
  phone. Nothing typed into the assistant leaves the phone.
* **Catalog** (`LocalModels`, all openly licensed and downloadable without an account, hash pinned):
  * **Gemma 4 E2B** (Apache 2.0, 2.59 GB): the most capable practical on-device model. Google's model card reports it
    running at about 47 tokens/s on a flagship (S26 Ultra) and using about 1.7 GB of memory on CPU; a mid-range phone
    will be much slower, so it is tested before use.
  * **Qwen 3 0.6B** (Apache 2.0, 347 MB): small and quick, basic answers.
  * Gemma 3 1B was dropped from the catalog: its files are gated behind a login and licence click-through, which
    cannot be automated.
* **Setup flow** (`LocalAiSetup`, runs in the app-wide scope so leaving the screen does not stop it):
  1. `SetupPlanner.recommend` picks Gemma 4 E2B when the phone has >= 5.5 GB RAM, enough storage and is not a low-memory
     phone, otherwise Qwen 3.
  2. `DeviceCheck`: 64-bit ARM, memory, storage, low-memory class, heat. Hard failures stop here with a plain reason.
  3. `ModelDownloader`: resumable (HTTP Range), HTTPS-only manual redirects, progress. Large downloads on mobile data need
     the user to allow it.
  4. SHA-256 of the file is compared with the pinned hash; a mismatch deletes the download.
  5. `LocalLlm.benchmark()`: load time, a streamed paragraph for speed (time to first word, tokens/s), then two accuracy
     prompts. `BenchmarkScoring.verdict` -> Good (>= 8 tokens/s and first word <= 4 s), Usable (>= 3), Too slow, or Poor
     answers.
  6. Good or Usable turns the feature on; otherwise it is off and `SetupPlanner.fallbackFor` offers the next smaller
     model (one more tap).
* **Where it lives**: `files/models` (private storage, outside the encrypted vault and backups; it is a public model).
* **Unit-tested**: device checks, scoring and quality checks, stream joining, planner and catalog integrity, download
  maths. Model loading, the actual download and the benchmark can only be exercised on a phone.
* **Privacy text** names the one-off download from Hugging Face.
* **Unknowns to learn on the A34**: real tokens/s, whether the GPU path is used (the Mali-G68 is old), and whether
  LiteRT-LM's message objects print as plain text via `toString()` (if wrapped, adjust `LocalLlm`).

## Assist everywhere (AI in every module)

One shared mechanism, so no feature module contains AI code:

* `core-ui/AiAssist.kt`: the `AiAssist` interface, `AiUse` (what can be asked), `AiStyle`, and `AiAssistButton`, a sparkle
  icon that opens a menu of uses, runs the request, and shows the answer with **Use this / Copy / Discard** and style
  chips to re-run. The app shell provides the implementation through `LocalAiAssist`; with AI off the button just
  explains how to turn it on.
* `AiAssistImpl` (app) decides where it runs: the on-device model if it passed its test, else the user's cloud provider
  if a key is saved (then the exact text is shown and must be confirmed), else nowhere.
* **Where the sparkle appears**: Notes (fix, clearer, shorter, summarize, action items, title; works on the selection or
  the whole note), Plans (break a goal into steps that are added to the checklist; clearer notes), Achievements (write it
  up, fix, clearer), Work tasks (steps, clearer), Appreciation (polish, fix, summarize), Work "Today at a glance" (plan my
  day from open tasks), Job applications (follow-up email, interview questions), Learning (study plan), Finance entry
  (suggest a category from the note, constrained to your categories) and Finance dashboard ("Explain this month" from the
  month's own figures).

### Answer styles: Fast / Normal / Accurate
`Style` in `core-ai/assist` maps each to model settings. They can be set as the default in Settings -> AI assistant ->
Answer style and changed per request in the answer dialog.

| Style | temperature | topK | topP | max length | self-check |
|---|---|---|---|---|---|
| Fast | 0.3 | 20 | 0.9 | 450 chars | no |
| Normal | 0.5 | 40 | 0.95 | 1400 chars | no |
| Accurate | 0.1 | 10 | 0.85 | 2600 chars | yes (a second pass checks the draft against the source) |

Temperature and topK/topP are passed to LiteRT-LM through `SamplerConfig`. LiteRT-LM exposes no max-token setting in
this version, so length is capped by stopping the stream at `maxChars`, which is also the biggest lever for speed. Fast
also gets a "be brief" system instruction; Accurate gets a "double-check numbers" one. Cloud providers receive the
temperature (Gemini, Claude) and a token cap; OpenAI keeps its default temperature because some newer models reject others.

### Safety nets that do not depend on the model
* `NumberGuard` compares numbers in the answer with the source: it warns about **invented numbers** (all uses) and, for fix /
  clearer / polish, about **numbers that disappeared**. This matters most for money.
* Prompts tell the model to stay inside the text, answer in the user's language and reply with the result only.
  `Cleanup` strips `<think>` blocks some models print.
* `LocalLlmHolder` keeps the model loaded for two quiet minutes so repeat requests skip the load, then frees the memory;
  it also frees it whenever the app locks.
* Unit-tested: styles, prompts (every id the app uses has a template), number guard, cleanup.
